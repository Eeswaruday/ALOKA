# ALOKA Admin setup

The public site remains static HTML, CSS and vanilla JavaScript. `/admin/login/` is only a login screen; every admin operation is checked by `api/admin.php`. Admin auth is a separate PHP session and does not replace Clerk for ordinary users. No administrator registration route or database is included.

## 1. Configure the initial administrator on the PHP host

Use PHP 8.1+ with cURL and sessions. Generate the password hash on a trusted machine; the password is read from a hidden PowerShell prompt, piped to the CLI-only PHP helper, and never written to a frontend file or browser:

```powershell
$secure = Read-Host 'Initial ALOKA admin password' -AsSecureString
$pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secure)
try {
  $plain = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer)
  $plain | php api/hash-admin-password.php
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer)
  $plain = $null
  Remove-Variable secure,pointer,plain -ErrorAction SilentlyContinue
}
```

Copy the resulting hash directly into the PHP host's protected environment settings. Never send the password or hash to the browser, Vercel, chat, source control, or logs. Set:

- `ADMIN_ENABLED=1`
- `ADMIN_EMAIL=uday90925@gmail.com`
- `ADMIN_PASSWORD_HASH=<hash generated by the CLI helper>`
- `ADMIN_FORCE_PASSWORD_CHANGE=1`
- `ALOKA_PRIVATE_DIR=<persistent writable directory outside the web root>`
- `ALLOWED_FRONTEND_ORIGINS=<exact HTTPS frontend origin>`

The first successful login must change the initial password. The new hash and an initialization marker are saved in `ALOKA_PRIVATE_DIR`; back up that directory securely. If the marker exists but its state file is missing, login fails closed instead of recreating the initial account. To disable access, set `ADMIN_ENABLED=0` or remove the credential environment variables. There is no public recovery or registration route.

For a PHP host behind a TLS proxy, configure the proxy to set `X-Forwarded-Proto: https`. Cross-origin deployments require HTTPS and exact CORS origin configuration. Keep `ALOKA_PRIVATE_DIR` writable by PHP, persistent across deploys, and outside the document root.

## 2. Connect the GitHub repository

Create a GitHub fine-grained access token limited to the selected repository with Contents read/write access. Configure on the PHP host:

- `GITHUB_TOKEN=<private token>`
- `GITHUB_REPOSITORY_OWNER=<owner>`
- `GITHUB_REPOSITORY_NAME=<repo>`
- `GITHUB_PRODUCTION_BRANCH=main` (or the actual production branch)
- `GITHUB_DRAFT_BRANCH=aloka-drafts`

The admin API creates the draft branch from production on first use. File edits, uploads and deletions commit only to the draft branch. Publish compares the exact changed file list and merges it to production only after the admin confirms.

## 3. Deploy frontend and PHP separately

Deploy the project root to Vercel as a static site. `api/` is excluded from the static deployment and does not execute there. Deploy the project’s `api/` PHP endpoints to a PHP-compatible host over HTTPS. Configure the frontend API endpoint in `admin/admin-config.js` to that host's full `https://.../api/admin.php` URL, and add the exact Vercel production origin to `ALLOWED_FRONTEND_ORIGINS` on PHP. Do not add PHP secrets to Vercel environment variables or frontend JavaScript.

Run `php -l api/admin.php`, `php -l api/admin-common.php`, and `php -l api/hash-admin-password.php` before deploying. Keep Clerk's existing config separate; regular users continue to sign in through Clerk.

Resend is not used by the admin login or password change flow. Configure a Resend key only if an email feature is added later.


## PHP upload settings

Set PHP upload limits to allow two files per request, each up to 2 MB: `upload_max_filesize=2M`, `post_max_size=6M`, `max_file_uploads=2`, and `max_execution_time=120`. Folder uploads are sent in small batches; if a batch fails, completed batches remain drafts and nothing is published.
